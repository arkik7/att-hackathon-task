# PAY-118: Duplicate charge references after retry

Investigating · 2026-08-20

Two charge documents have the same order reference and idempotency key. Both carry succeeded status from ledger-sim. The client expected the retry contract to reuse the first charge ID.

Capture exact request headers and inspect how the key is used inside the handler. A serialized write queue prevents overlapping file writes but does not by itself establish request deduplication. No external payment provider is involved.
